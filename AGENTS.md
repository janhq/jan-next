# Repository Guidelines

## Project Overview

open-waifu is a personal fork of [Jan](https://github.com/janhq/jan) for hobby and learning: a local-first AI chat app (future waifu chat) on Tauri 2, macOS and Windows desktop only.

- **Removed from upstream; do not reintroduce:** CI, the docs site, Linux and mobile targets, MLX, the ADKs, the headless `jan` CLI/TUI and `protocol/`, the e2e/WebDriver hooks, the auto-updater, PostHog/GA telemetry, the Claude Code integration, Cowork (sidebar tab, `/cowork`, its frontend agent runner and its Rust/Tauri support), built-in web search (use a browser MCP server instead), and named remote providers (OpenAI, Anthropic, Gemini, Azure, ...).
- **Names stay `jan`:** identifiers, crate names and package names still say `jan` / `@janhq/*`. Keep them unless asked to rebrand.

## Architecture & Data Flow

```text
React UI (web-app) ──ServiceHub──┬─ Tauri* services ──invoke──► Rust commands (src-tauri/src/core)
                                 └─ Default* services ──window.core.api──┘   ├─ plugins (src-tauri/plugins/tauri-plugin-*)
extension host (Web Workers, postMessage) ──ServiceRegistry / guest-js──►    ├─ local OpenAI-compatible server (core/server)
                                                                             └─ agent loop (core/agent) ──ToolInvoker──► agent-tools plugin
llama.cpp engine: jan-llama-worker process (plugin llamacpp), fronted by the local server
```

- **UI → Rust:** always go through `getServiceHub()` / `useServiceHub()` (`web-app/src/hooks/useServiceHub.ts`).
  - `web-app/src/services/index.ts` defines the `ServiceHub` interface and `PlatformServiceHub`.
  - Each `services/<name>/` folder has a `default.ts` and optionally a `tauri.ts`. Only 13 services have a Tauri variant.
  - The rest (threads, messages, models, assistants, rag, uploads, projects) stay `Default*` and reach Rust through `window.core.api`, which `ExtensionProvider.tsx` sets up.
  - Getters throw if called before `initializeServiceHub()`.
- **Rust commands:** a single `generate_handler!` list inside `invoke_commands_with_extras!` in `src-tauri/src/lib.rs`.
  - A new `#[tauri::command]` that is missing from that list fails only at runtime.
  - Plugins and `AppState` are registered in `run()` in the same file.
- **Plugins:** each `src-tauri/plugins/tauri-plugin-<name>/` has three parts:
  - the Rust plugin;
  - a `guest-js/` TS wrapper, published as the `@janhq/tauri-plugin-<name>-api` package;
  - a `COMMANDS` list in `build.rs` that generates the permissions under `permissions/autogenerated/`.

  App permissions live in `src-tauri/capabilities/*.json`.
- **Extensions:** the built-ins in `extensions/*-extension` run in Web Workers through `web-app/src/lib/extensions/` (`host.ts` `getExtensionHost()`, `builtins.ts`, `worker-runtime.ts`, `dispatcher.ts`, `watchdog.ts`).
  - Each extension exports `activate(ctx)` against `@janhq/extension-api`.
  - Engines share services through `ServiceRegistry` / `ServiceKeys` (`core/src/browser/host/services.ts`). `provide` throws on a duplicate key.
  - `AIEngine` / `EngineManager` in `core/` are a legacy layer that still works.
- **Local API server:** `src-tauri/src/core/server/`.
  - `proxy.rs` is the hyper 1.x server. Routes: `/chat/completions`, `/completions`, `/embeddings`, `/models`, `/orchestrations`, `/openapi.json` (no Swagger UI page, no Anthropic `/messages`).
  - `commands.rs` starts and stops it.
  - Auth is `Authorization: Bearer` or `x-api-key`. The OpenAPI spec is `src-tauri/static/openapi.json`.
- **Agent:** `src-tauri/src/core/agent/loop.rs` (`run_orchestration_steered()`, the `ToolInvoker` and model-invoker traits) and `subagent.rs`. Built-in tools come from `tauri-plugin-agent-tools`.
  - The app is desktop-only now: the shell is always sandboxed and escalation is never offered.
  - Comments that mention "the CLI" or Linux are upstream leftovers. `default_jan_skill.md` still mentions `jan cli`.
- **Model providers:** exactly two kinds. `llamacpp` (the local engine) and user-added OpenAI-compatible endpoints (name, base URL, API key), all spoken to as OpenAI `/chat/completions`.
  - web-app: `lib/model-factory.ts` sends everything but llamacpp through `createOpenAICompatibleModel`; `lib/providerCaps.ts` holds the llamacpp caps and the permissive custom set.
  - Rust agent: `core/agent/upstream.rs` / `genai_bridge.rs` use the OpenAI adapter only. Do not add vendor SDKs or per-vendor converters.
- **Threads:** stored as files, `thread.json` plus `messages.jsonl` per thread under the Jan data folder, with per-thread async locks (`core/threads/`).
- **Engine:** llama.cpp is built from source into `jan-llama-worker` (`plugins/tauri-plugin-llamacpp/src/engine/`, `src/bin/jan-llama-worker.rs`). The pinned llama.cpp commit is in that plugin's `build.rs`, and the source is cloned to `vendor/llama.cpp`.
- **State:** zustand stores in `web-app/src/hooks/`, `stores/` and `lib/`. Persistence is owned by the backend (`lib/backendStorage.ts` / `fileStorage` → Rust `settings_get`/`settings_set`), not localStorage.

## Key Directories

| Path | Purpose |
|---|---|
| `web-app/src/routes/` | TanStack file routes (`threads/$threadId.tsx`, `settings/providers/$providerName.tsx`) |
| `web-app/src/containers/`, `components/` | Feature components vs reusable UI (`components/ui/`) |
| `web-app/src/services/<name>/` | ServiceHub implementations (`default.ts`, `tauri.ts`, `__tests__/`) |
| `web-app/src/lib/extensions/` | Extension host, worker runtime, permissions |
| `web-app/src/locales/<lang>/<ns>.json` | i18n strings, 17 locales |
| `core/` | `@janhq/core`: shared types, engine base classes, extension context, `ServiceRegistry` |
| `extensions/` | Built-in extensions: assistant, download, llamacpp, rag, vector-db |
| `packages/extension-api`, `packages/extension-runtime` | Extension SDK, and the worker runtime (realm lockdown, prelude) |
| `src-tauri/src/core/` | Rust app: `agent/`, `server/`, `threads/`, `mcp/`, `filesystem/`, `downloads/`, `system/` |
| `src-tauri/plugins/` | Tauri plugins: agent-tools, extensions, hardware, llamacpp, rag, vector-db. Separate Yarn root |
| `src-tauri/utils/` | `jan-utils` crate: shared Rust helpers (CORS, paths, system) |
| `src-tauri/build-utils/` | Scripts: `download-bin.mjs` (bun, uv, sqlite-vec → `resources/bin`), `stub-tauri-resources.mjs` (test stubs), `build-windows-icon.mjs`, `fetch-engine-source.sh`, `check-engine-toolchain.sh`, `stage-engine.sh` |
| `src-tauri/tests/` | Integration tests; `fixtures/upgrade/<version>/` holds old user data for upgrade-compat tests |

## Development Commands

```bash
make dev                      # install → download:bin → engine build (skipped if toolchain missing) → tauri dev
make dev-web                  # UI only in a browser (http://localhost:1420); no extension build
make build                    # production build: release engine + tauri build (nsis/msi on Windows)
make test                     # lint + vitest + all Rust tests
make lint                     # eslint (web-app) == yarn lint
make clean                    # node_modules, dist, src-tauri/target, resources, vendor/llama.cpp
make build-engine-dev JAN_ENGINE_VARIANT=cpu   # cpu|vulkan|metal|cuda12|cuda13|hip, join with '-' (default vulkan)
```

- **Build order:** plugin guest-js (`yarn build:tauri:plugin:api`) → `yarn build:core` → `yarn build:extensions` → web → tauri.
  - The web-app imports extensions from `extensions/*/dist/index.js`, so rebuild an extension after editing it.
  - The same applies to `core/` and the plugin `guest-js/`.
- **Engine knobs:** `JAN_ENGINE_CUDA_ARCHS`, `JAN_ENGINE_HIP_TARGETS`, `JAN_ENGINE_JOBS`, `JAN_ENGINE_VULKAN_FALLBACK` (default 1). The build log goes to `src-tauri/target/engine-build.log`.
- **Windows:** run make from Git Bash, because the engine and stage scripts are `sh`. Engine builds need VS 2022 Build Tools, LLVM (`clang-cl`), Ninja and CMake, plus the CUDA Toolkit for CUDA builds.
- **Type check:** `cd web-app && yarn tsc -b` (strict, `noUnusedLocals`, `noUnusedParameters`).
- **Rust check:** `cargo check --manifest-path src-tauri/Cargo.toml` (desktop), and add `--no-default-features --features test-tauri --tests` for the test build.

## Code Conventions & Common Patterns

- **TS formatting:** `.prettierrc` sets no semicolons, single quotes, `trailingComma: es5`. Prettier is not installed or run by any script, so match the style by hand.
  - ESLint flat config: `web-app/eslint.config.js` (typescript-eslint, react-hooks, react-refresh).
- **Imports:** `@/` = `web-app/src`.
- **Naming:**
  - Hooks are `useX.ts`.
  - Tauri commands are snake_case, and the TS `invoke('cmd_name', …)` string must match exactly.
  - Plugin commands are `plugin:<name>|cmd`, always called through the plugin's guest-js.
- **Extensions never call raw Tauri.** `extensions/no-raw-tauri-invoke.test.ts` fails on `@tauri-apps/*` imports or `plugin:<name>|` strings in `extensions/*/src`. Use `@janhq/core` or the guest-js wrappers instead.
  - The web-app has legacy direct `invoke` imports; new code should use ServiceHub.
- **Rust errors:** Tauri commands are `async fn … -> Result<T, String>` taking `State<'_, AppState>`.
  - The agent loop also returns `Result<_, String>` and maps errors for the UI with `ui_error`.
  - Server internals use `Box<dyn Error + Send + Sync>`.
- **Async:** tokio (`tokio::spawn`, `tokio::sync::Mutex`, `Notify`) and `tauri::async_runtime`.
- **Cargo features (`src-tauri/Cargo.toml`):**
  - `default` includes `desktop`, which is `deep-link` + `extensions` + `hardware` + `tauri-app`. `tauri-app` gates the whole Tauri runtime, and `build.rs` runs `tauri_build` only under it.
  - `test-tauri` is for tests and adds `tauri/test`. The `Jan-Desktop` bin requires `desktop`.
  - New platform code: macOS and Windows only, with no `linux`/`android`/`ios` cfgs.
- **i18n:** add keys to `web-app/src/locales/en/<ns>.json`. `locales/__tests__/localeKeys.test.ts` checks the other locales. Import `useTranslation` from `web-app/src/i18n/react-i18next-compat.ts`.
- **Comments:** explain why, not what. The existing code follows this heavily.
- **Commits:** Conventional Commits with a scope, e.g. `fix(agent): …`, `feat(llamacpp): …`, `fix(web-app): …`.

## Important Files

- **Entry points:** `web-app/src/main.tsx` (`boot()`), `web-app/src/providers/ExtensionProvider.tsx` (sets up `window.core`, activates extensions), `src-tauri/src/lib.rs` (`run()`, the command list).
- **Config:**
  - `package.json`: workspaces `core`, `web-app`, `extensions/*`, `packages/*`, plus scripts.
  - `Makefile`.
  - `src-tauri/Cargo.toml`: features, and a size-optimised release profile.
  - `src-tauri/tauri.conf.json`, plus `tauri.macos.conf.json` and `tauri.windows.conf.json`.
  - `web-app/vite.config.ts`: `define` flags such as `IS_TAURI` and `PLATFORM`, and the extension aliases.
  - `vitest.config.ts`.
- **Do not hand-edit:**
  - `web-app/src/routeTree.gen.ts`;
  - `packages/extension-api/api-report.d.ts` (byte-compared, LF);
  - `src-tauri/plugins/*/permissions/autogenerated/`;
  - generated icons in `src-tauri/icons/` (only the `icon.png` sources are tracked);
  - `src-tauri/resources/`, `src-tauri/gen/`, `vendor/llama.cpp`.
- **Identifier:** the bundle identifier is still `jan.ai.app`. It sets the user-data path, so changing it orphans existing data.
- **Version mismatch:** `web-app/package.json` says `0.7.6`, while Tauri and Cargo say `0.8.8`. The Vite `VERSION` define reads the web-app value.

## Runtime/Tooling Preferences

- **Node and Yarn:** Node 20+ with Yarn 4.5.3 via corepack (`corepack yarn …`). Do not use npm or bun. The settings are `nodeLinker: node-modules` with hoisting limited to workspaces.
- **Plugin workspace:** `src-tauri/plugins/` is its own Yarn root (`cd src-tauri/plugins && yarn install`).
- **Rust:** pinned in `rust-toolchain.toml` (1.98.0, clippy, rustfmt).
  - Only `src-tauri/Cargo.lock` is tracked, and only the main crate builds with `--locked`. The standalone plugin and `utils` lockfiles are gitignored.
  - After removing a dependency from the app, run `cargo update --workspace --manifest-path src-tauri/Cargo.toml` so `--locked` still passes.
- **No git hooks:** nothing runs on commit. Run `yarn lint` yourself before committing web-app changes.

## Testing & QA

- **JS:** Vitest multi-project (`vitest.config.ts`).
  - `yarn test` runs `test:core`, `test:web`, `test:ext` and `test:packages`.
  - One file: `corepack yarn vitest run --project @janhq/web-app path/to/file.test.ts`.
- **JS placement and setup:** tests go in `__tests__/` next to the source, named `*.test.ts(x)`.
  - Web tests run in jsdom.
  - `web-app/src/test/setup.ts` mocks `@/hooks/useServiceHub` globally with a full `mockServiceHub`, and stubs `matchMedia`, `ResizeObserver` and `globalThis.core.api`.
- **Mocking Tauri:** use `vi.mock('@tauri-apps/api/core', () => ({ invoke }))`, with `vi.hoisted` for shared fns. Plugin APIs are mocked the same way, e.g. `@janhq/tauri-plugin-llamacpp-api`.
- **Rust:** `make test-rust` runs `stub-tauri-resources.mjs`, then four test runs:
  - the main crate: `cargo test --locked --no-default-features --features test-tauri -- --test-threads=1`;
  - the hardware, extensions and llamacpp plugins;
  - `utils`;
  - `tauri-plugin-agent-tools` with `--no-default-features --lib --test sandbox_spawn`.
- **One Rust test:** `cargo test --manifest-path src-tauri/Cargo.toml --no-default-features --features test-tauri <name> -- --test-threads=1`.
- **Rust test layout:** tests are inline `#[cfg(test)] mod tests` or a sibling `tests.rs`. Integration tests are in `src-tauri/tests/` (`upgrade_compat.rs`) and in the plugins' `tests/` folders.
- **Rust test isolation:** test data goes to the OS temp dir (`get_jan_data_folder_path` under `cfg!(test)`). Use `with_temp_home` (`core/agent/global_config.rs`) for anything touching `~/.jan`.
- **Environment-sensitive tests:**
  - Git-dependent tests return early when git is missing.
  - The context-file tests fail if a `JAN.md` exists in an ancestor directory such as `~`.
  - With `CI` set, the symlink tests in agent-tools fail instead of skipping on Windows without Developer Mode.
  - `gate`, `monitor`, `worker-runtime.test.ts` (flood tests) and `watchdog.test.ts` are timing-sensitive.
  - Rerun a failing file alone, and compare against a clean `HEAD` checkout before investigating.
- **Coverage:** no thresholds; `yarn test:coverage` (v8) is available.
- **UI changes:** verify the real flow in the running app. Unit tests alone do not cover it.
