# L13: MCP servers, skills, presets, automation, permissions

## Summary

Settings > MCP Servers (add, enable, tool list, failure), Settings > Skills (search, add a folder, use, edit), agent presets (Settings > Agent presets and More > Presets), Automation tasks, permission presets (sandbox and approval), what the agent can and cannot see, and the `/goal` and `/plan` commands.

Needs: the seed, one real provider key for the cases marked `real` (export exactly that key before launch, see the README), the network for `npx`, and Node.js. Port block 9530. Test MCP server: `npx -y @modelcontextprotocol/server-everything` over stdio (command `npx`, arguments `-y` and `@modelcontextprotocol/server-everything`, one per line), and over HTTP with `PORT=9534 npx -y @modelcontextprotocol/server-everything streamableHttp` serving `http://127.0.0.1:9534/mcp`. If that package changes, use any MCP server with an echo-style tool and one with arguments. Make `/tmp/jan-qa/L13/skills/qa-haiku/SKILL.md` with YAML frontmatter `name: qa-haiku` and a `description:` line, and a body that says to answer only with a haiku about the topic. Make two folders, `/tmp/jan-qa/L13/proj` (the project used for the agent cases, with a `hello.txt`) and `/tmp/jan-qa/L13/outside`, and a second project `/tmp/jan-qa/L13/other` holding `secret-note.txt` that says `other-project-7731`.

Provider key: the recipe's `unset` loop removes every key from the shell. Export exactly one real key before launch for the `real` cases and none for the `any` ones. The default model on a fresh home is `anthropic/claude-sonnet-5-5[1m]`, so a `real` lane picks the model that key belongs to before the first send.
