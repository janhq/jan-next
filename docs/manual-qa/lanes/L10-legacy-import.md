# L10: Legacy import from the original Jan

## Summary

The first-launch offer to bring over the original Jan app's chats, assistants, model providers with their keys, and MCP servers; the Import from Jan dialog and its progress; stopping, retrying and partial failure; an imported chat getting a reply; the source folder staying untouched; and Settings > Built-in plugins > Import from Jan.

Needs: the seed and a test copy of an original Jan data folder (a throwaway Jan profile, never a real person's chats; the fixture is described below the table). The lane's launch recipe sets `HOME=/tmp/jan-qa/L10/fakehome`, and the app looks for the original data at the path under it: `$HOME/Library/Application Support/Jan/data` on macOS, `$XDG_DATA_HOME/Jan/data` or `$HOME/.local/share/Jan/data` on Linux, `%APPDATA%\Jan\data` on Windows. Before each launch copy the fixture there with `cp -cR` (a fresh copy for every case that says "fresh"), and take a checksum list of it: `cd "<that data folder>" && find . -type f -print0 | xargs -0 shasum | sort > /tmp/jan-qa/L10/before.txt`. Port block 9500. Start the mock server on 9503. One real provider key (throwaway) is needed for L10-18. Keychain items created by the provider import go in the result file's Cleanup.

Provider key: the recipe's `unset` loop removes every key from the shell. Export one real throwaway key only for L10-14 and L10-18; the other cases use the stub model, so switch the picker to `qa-mock / mock-model` before the first send (the default model on a fresh home is `anthropic/claude-sonnet-5-5[1m]`).
