# L11: Persistence, restart, crash, offline, performance

## Summary

What survives quitting, closing the window, a crash (`kill -9`), a dead model server, no network, a full disk and a long idle; how the app behaves with a 500-message chat, a 200,000-character message and 30 chats; startup time and memory budgets; two instances on one home.

Needs: the seed and the lane's mock server. Port block 9510; start the server on 9513 with `--sequence success --repeat-last` unless a case says otherwise. Run the timing cases (L11-01, L11-02, L11-17, L11-22) alone, with no other Electron instance and no build running, and record the numbers in the result file. Processes to know: the Electron main process, its renderer and helper processes, the Jan host process (its inspector is on 9512), and the llama.cpp worker when a local model is loaded; list them with `ps -axo pid,rss,%cpu,command | grep -i electron`. Make a 500-message chat by importing the 500-message chat of the L10 fixture (see L10-24) through Settings > Built-in plugins > Import from Jan with the fixture at the fake home's original Jan path, or by sending 250 short messages with a keyboard macro. Make 30 chats the same way, with Cmd+N, "hi" and Enter repeated.

Provider key: none. The recipe's `unset` loop removes every key from the shell, so a send on the default model must fail with a missing-credential message. Switch the picker to `qa-mock / mock-model` before the first send: the default model on a fresh home is `anthropic/claude-sonnet-5-5[1m]`.

Budgets used below are targets for a 10-core, 32 GB laptop with nothing else running. A miss is a finding at the case's severity, not a blocker: record the number either way.
